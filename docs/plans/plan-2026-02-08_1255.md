# Plan: Dynamic Pipeline Designer with DAG Execution

**Date:** 2026-02-08 12:55  
**Status:** Proposed

---

This plan transforms the current hardcoded 6-agent pipeline into a fully user-configurable, data-driven system. Users will define custom agents, compose them into pipelines via a visual drag-and-drop canvas, configure retry policies per step, and export/import entire configurations. The pipeline engine is a DAG runner supporting parallel execution of independent steps. The Home page pipeline viewer dynamically renders whatever pipeline is active, and 4 built-in pipeline templates ship out of the box.

## Phase 1 — Core Models & Agent Definition Repository

### Step 1 — AgentDefinition Model

Create `src/elbruno.Doc2Code.Core/Models/AgentDefinition.cs` — new `sealed class AgentDefinition` with properties: `AgentKey` (unique string), `DisplayName`, `IsBuiltIn` (bool), `SystemPrompt`, `UserPromptTemplate`, `ModelId`, `Temperature` (double), `SupportsTools` (bool), `ExpectedInputKeys` (List\<string\>), `OutputKey` (string), `Description` (string). Built-in agents have `IsBuiltIn = true`; their `DisplayName`, `SystemPrompt`, and `UserPromptTemplate` are read-only at the UI level; they cannot be deleted.

### Step 2 — PipelineDefinition Model

Create `src/elbruno.Doc2Code.Core/Models/PipelineDefinition.cs` — new models:

- `PipelineDefinition`: `Id` (string GUID), `Name`, `Description`, `IsDefault` (bool), `IsActive` (bool), `Version` (int), `CreatedAtUtc`, `UpdatedAtUtc`, `Steps` (List\<PipelineStepDefinition\>), `Edges` (List\<PipelineEdge\>)
- `PipelineStepDefinition`: `StepId` (string), `AgentKey` (references `AgentDefinition`), `RetryPolicy` (nullable `StepRetryPolicy`), `PositionX`/`PositionY` (double, for canvas layout)
- `StepRetryPolicy`: `MaxRetries` (int), `QualityGateField` (string, e.g. `"scoreOutOf100"`), `AcceptanceThreshold` (int)
- `PipelineEdge`: `SourceStepId`, `TargetStepId`, `OutputKeyMapping` (string — which key the target reads from source's output)

### Step 3 — PipelineDataBag

Create `src/elbruno.Doc2Code.Core/Models/PipelineDataBag.cs` — a `sealed class PipelineDataBag` wrapping a `Dictionary<string, JsonElement>` with typed convenience methods: `Set<T>(string key, T value)`, `Get<T>(string key)`, `TryGet<T>(string key, out T)`, `ContainsKey(string)`, `Keys`. This is the uniform I/O contract for all agents in a dynamic pipeline. Include a `RequirementsDocument? OriginalSpec` property seeded at pipeline start.

## Phase 2 — DAG Pipeline Engine

### Step 11 — Pipeline Validator

Create `src/elbruno.Doc2Code.Core/Pipeline/PipelineValidator.cs` — `PipelineValidator` with:

- `Validate(PipelineDefinition, IReadOnlyList<AgentDefinition>)` returns `PipelineValidationResult` (list of errors/warnings)
- Checks: all step `AgentKey` references exist; graph is connected (reachable from root steps); no cycles (topological sort); every step's `ExpectedInputKeys` are satisfied by upstream edges' `OutputKeyMapping`; at least one root step (no inbound edges); at least one leaf step (no outbound edges)

### Step 12 — Topological Sorter

Create `src/elbruno.Doc2Code.Core/Pipeline/TopologicalSorter.cs` — Kahn's algorithm implementation that takes `PipelineDefinition` and returns execution levels (`List<List<PipelineStepDefinition>>`) where each inner list is a parallelizable batch. Throws on cycle detection.

### Step 13 — IDynamicAgent Interface

Create `src/elbruno.Doc2Code.Core/Abstractions/IDynamicAgent.cs`:

```csharp
interface IDynamicAgent
{
    string AgentKey { get; }
    string DisplayName { get; }
    Task<PipelineDataBag> RunAsync(PipelineDataBag input, IProgress<AgentLogEntry> log, CancellationToken ct);
}
```

### Step 14 — DynamicLlmAgent

Create `src/elbruno.Doc2Code.Agents/DynamicLlmAgent.cs` — a concrete `IDynamicAgent` for user-defined agents. It takes an `AgentDefinition`, `IChatClient`, and `ToolRegistry`. It uses the definition's `SystemPrompt`, interpolates `UserPromptTemplate` with bag values (using `{key}` placeholder syntax), calls the LLM, parses JSON response into a `JsonElement`, and stores it in the bag under `OutputKey`. Reuses `LlmAgentBase` streaming/retry/repair logic via composition (internal helper or inheritance from a new non-generic base).

### Step 15 — BuiltInAgentAdapter

Create `src/elbruno.Doc2Code.Agents/BuiltInAgentAdapter.cs` — adapts each existing `LlmAgentBase<TIn, TOut>` agent into `IDynamicAgent`. For each built-in agent, reads typed inputs from `PipelineDataBag`, calls `RunAsync`, and writes the typed output back. Factory method `CreateAdapter(string agentKey, ...)` with a switch over the 6 built-in keys.

### Step 16 — Agent Factory

Create `src/elbruno.Doc2Code.Agents/AgentFactory.cs` — `IAgentFactory` interface + implementation. `Create(AgentDefinition)` returns `IDynamicAgent`: for built-in agents, wraps the existing singleton agents via `BuiltInAgentAdapter`; for custom agents, instantiates `DynamicLlmAgent`.

### Step 17 — DynamicPipelineRunner

Create `src/elbruno.Doc2Code.Agents/DynamicPipelineRunner.cs` — `DynamicPipelineRunner : IGenerationPipeline`:

- On `RunPipelineAsync`: loads the active `PipelineDefinition` from `ISettingsStore`, resolves all agent definitions, validates the graph via `PipelineValidator`, computes execution levels via `TopologicalSorter`
- Executes level-by-level: for each level, runs all steps in parallel (`Task.WhenAll`), collecting results into the shared `PipelineDataBag`
- For each step, respects `StepRetryPolicy`: if the output bag contains the `QualityGateField` and its numeric value is below `AcceptanceThreshold`, re-runs the step's predecessor (or the step itself) up to `MaxRetries` times — generalizing the current Reviewer pattern
- Reports progress via `IProgress<PipelineStatus>` using `StepIndex`, `TotalSteps`, `StepAgentKey`, and a computed `CompletionPercent` based on level position
- Calls `IRefreshableChatClient.RefreshAsync()` at start, reads tool toggles, propagates to agents

### Step 18 — Extend PipelineStatus

Extend `PipelineStatus` in `src/elbruno.Doc2Code.Core/Models/PipelineStatus.cs`: add `StepIndex` (int), `TotalSteps` (int), `StepAgentKey` (string), `ParallelPeers` (List\<string\> — names of agents running concurrently in the same level). Add `WorkflowStage.Custom` value with `CustomStageName` (string) property. Keep existing enum values for backward compat.

### Step 19 — Update DI Registration

Update DI registration in `src/elbruno.Doc2Code.ApiService/Program.cs`: register `IAgentFactory`, `PipelineValidator`, `TopologicalSorter`. Replace `AgentOrchestrator` → `DynamicPipelineRunner` as the `IGenerationPipeline` implementation. Keep existing agent singletons registered (used by `BuiltInAgentAdapter`).

### Step 20 — Update SignalR Protocol

Update `src/elbruno.Doc2Code.ApiService/Hubs/AgentLogHub.cs` — extend the `PipelineStatusChanged` broadcast payload to include the new fields (`StepIndex`, `TotalSteps`, `ParallelPeers`).

### Step 21 — Phase 2 Unit Tests

Add unit tests for the DAG engine: `TopologicalSorterTests` (linear chain, diamond, parallel branches, cycle detection), `PipelineValidatorTests` (valid pipeline, missing agent, cycle, unresolved input keys), `DynamicPipelineRunnerTests` (mock agents, verify execution order, retry behavior, parallel execution).

## Phase 4 — Pipeline Designer UI (Drag-and-Drop Canvas)

### Step 24 — Navigation Update

### Step 25 — Pipeline Designer Page

Create `src/elbruno.Doc2Code.Web/Components/Pages/PipelineDesigner.razor` + `.razor.cs` code-behind. Route: `@page "/pipeline-designer"`. Layout: 3-panel design:

- **Left sidebar — Agent Repository panel** (~250px wide): scrollable list of all `AgentDefinition` entries grouped by "Built-in" and "Custom". Each card shows `DisplayName`, `AgentKey`, `IsBuiltIn` badge. Drag handle for drag-to-canvas. "➕ New Agent" button at top opens the Agent Editor modal. Click on an agent card to select it and show its properties in the right panel.

- **Center — Pipeline Canvas** (flex-grow): an SVG/HTML canvas area rendered via JS interop. Nodes are positioned by `PositionX`/`PositionY` from `PipelineStepDefinition`. Arrows (SVG `<path>` elements) connect nodes per `PipelineEdge`. Interactions:
  - **Drop** an agent from the sidebar → creates a new `PipelineStepDefinition` at the drop coordinates
  - **Drag** a node → updates `PositionX`/`PositionY`
  - **Connect** two nodes (drag from output port on source to input port on target) → creates a `PipelineEdge`
  - **Select** a node → highlights it, shows properties in right panel
  - **Delete** a node (keyboard or context menu) → removes step + all connected edges
  - **Delete** an edge (click edge → delete)
  - Retry policy badge shown on nodes that have one

- **Right sidebar — Properties Inspector** (~300px wide): when a step node is selected, shows: agent display name, model override, temperature slider, retry policy (toggle + max retries + quality gate field + threshold), input/output key mappings. When an agent definition is selected (from left panel), shows: full agent properties (editable for custom, read-only for built-in except model/temperature).

- **Toolbar** (top of center panel): Save Pipeline, Load Pipeline (dropdown of saved pipelines), Clone, Delete, Set Active, Export JSON, Import JSON, Reset to Default, Validate (runs `PipelineValidator` and shows errors inline).

### Step 26 — Canvas JS Module

Create `src/elbruno.Doc2Code.Web/wwwroot/js/pipeline-canvas.js` — JS module for the drag-and-drop canvas. Use ELK.js (Eclipse Layout Kernel) for auto-layout, or a simpler custom implementation with manual positioning. Functions exposed to Blazor via `IJSRuntime`:

- `initCanvas(dotNetRef, containerId, pipelineJson)` — renders nodes + edges
- `onNodeMoved(stepId, x, y)` → callback to .NET
- `onEdgeCreated(sourceStepId, targetStepId)` → callback
- `onNodeSelected(stepId)` → callback
- `onNodeDeleted(stepId)` → callback
- `onEdgeDeleted(sourceStepId, targetStepId)` → callback
- `updateLayout(pipelineJson)` — re-render after changes
- `autoLayout()` — run ELK.js auto-layout and return new positions

### Step 27 — Agent Editor Modal

Create `src/elbruno.Doc2Code.Web/Components/Pages/AgentEditorModal.razor` — form for creating/editing custom agents: `DisplayName`, `AgentKey` (auto-generated slug from name, editable), `SystemPrompt` (textarea), `UserPromptTemplate` (textarea with `{key}` placeholder hints), `ModelId`, `Temperature` (slider), `SupportsTools` (toggle), `ExpectedInputKeys` (tag input), `OutputKey`, `Description`. ## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| **DAG vs ordered list** | Full DAG from the start | Enables parallel execution of independent agents (e.g., Testing ∥ Documentation). Uses Kahn's algorithm for topological sort and level-based parallel dispatch via `Task.WhenAll` |
| **Designer UX** | Full drag-and-drop canvas | Using JS interop with ELK.js for auto-layout. SVG-based canvas with HTML overlay nodes for rich content. Undo/redo via command stack pattern |
| **Pipeline templates** | 4 templates | Default (current 6-agent), Code Only, Quick Prototype, Full QA |
| **AgentProfile merge** | Merged into AgentDefinition | Single model for agent config; legacy migration in `SettingsStore` |
| **Universal I/O** | PipelineDataBag | All agents read/write a shared bag. Built-in agents wrapped via `BuiltInAgentAdapter` to preserve typed implementations internally |
| **Export security** | Excludes secrets | API keys, GitHub tokens, and Copilot tokens stripped from export bundles |
