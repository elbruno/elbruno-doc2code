## Task 1 — Connector Ports & Behavior Redesign

### Problem Statement

Currently:

- When an agent is added to the canvas, it is **auto-connected** to the previously last step (`Steps[^2]`), which is naive for non-linear DAGs and creates unwanted edges.
- The "Connect mode" uses a toolbar toggle + click-node-body workflow with no visual port indicators on the nodes themselves.
- `_buildNodeEl` in `pipeline-canvas.js` renders simple labeled boxes with no connector port circles.
- Bookend nodes (`pd-node-bookend` CSS class) exist in the Razor styles but are never applied in JS.
- Edge drawing uses node edges (right/left) as connection points — no dedicated port coordinates.
- There are no visual cues on the canvas during connect mode (no node highlighting, no cursor change in JS).

### Steps

#### Step 1: Remove auto-connect from `AddAgentToCanvasAsync`

**File:** `src/elbruno.Doc2Code.Web/Components/Pages/PipelineDesigner.razor.cs`

Delete the `if (_activePipeline.Steps.Count > 1)` block in `AddAgentToCanvasAsync` (around line 175) that creates an automatic edge from `Steps[^2]` to the new step. Agents will land on the canvas **unconnected**.

#### Step 2: Add connector port rendering in JS

**File:** `src/elbruno.Doc2Code.Web/wwwroot/js/pipeline-canvas.js`

Modify `_buildNodeEl` to append two port elements to each node:

- **Output port** (right side): `<div class="pd-port pd-port-out" data-port="out"></div>` — small green circle positioned at `right: -6px; top: 50%`
- **Input port** (left side): `<div class="pd-port pd-port-in" data-port="in"></div>` — small green circle positioned at `left: -6px; top: 50%`

Bookend exceptions:

- `step-document-input` (start node) → **output port only** (no input port)
- `step-generated-assets` (end node) → **input port only** (no output port)

Attach `pointerdown` on output port → begins connection drag (not node drag). Use `stopPropagation` on port events so they don't trigger node selection or node drag.

#### Step 3: Implement port-to-port connection drag in JS

**File:** `src/elbruno.Doc2Code.Web/wwwroot/js/pipeline-canvas.js`

Add connection drag state:

```javascript
let _connectState = { sourceStepId: null, active: false };
```

Behavior:

1. **Output port `pointerdown`:** Set `_connectState.sourceStepId`, `active = true`. Begin drawing a temporary SVG edge from the output port position to the mouse cursor.
2. **`pointermove` while active:** Redraw the temporary dashed edge line to follow the cursor position.
3. **Input port `pointerup`:** If `_connectState.active`, fire `_dotNetRef.invokeMethodAsync("OnEdgeCreatedJs", sourceStepId, targetStepId)`. Clear state, remove temp line.
4. **`pointerup` on canvas background:** Cancel connection, remove temp line.

Visual feedback during drag:

- Temporary edge drawn as dashed line (`stroke-dasharray: 5,5`) in yellow (`#d4c85a`)
- Valid target input ports glow on hover (class `pd-port-valid-target`)

#### Step 4: Update edge drawing for direction clarity

**File:** `src/elbruno.Doc2Code.Web/wwwroot/js/pipeline-canvas.js`

Modify `_redrawEdges`:

- Edges connect from the **output port center** (`right edge + 6px`) to the **input port center** (`left edge - 6px`) instead of node edges directly.
- Make arrowheads slightly larger: **10px** instead of 8px.
- Fill arrowheads with brighter green (`#33ff77`) for visibility.
- Keep the cubic Bézier curve approach, adjusted for port-origin coordinates.

#### Step 5: Add bookend node styling in JS

**File:** `src/elbruno.Doc2Code.Web/wwwroot/js/pipeline-canvas.js`

In `_buildNodeEl`, when `step.isBookend === true`:

- Add CSS class `pd-node-bookend` to the node element.
- Append a `<span class="pd-bookend-badge">START</span>` badge for Document Input, or `<span class="pd-bookend-badge">END</span>` for Generated Assets.

The CSS for `pd-node-bookend` and `pd-bookend-badge` already exists in the Razor `<style>` block.

#### Step 10: Create Pipeline Designer documentation

**New file:** `docs/pipeline-designer.md`

Comprehensive guide covering:

1. **Overview** — What the Pipeline Designer does; relationship to pipeline execution
2. **Layout** — Three-panel description:
   - Left sidebar: Agent repository (built-in + custom) and pipeline templates
   - Center: Canvas with toolbar
   - Right sidebar: Properties inspector
3. **Adding agents** — Click any agent in the left sidebar to place it on the canvas (lands unconnected)
4. **Creating connections** — Two methods:
   - **Primary (drag):** Drag from an output port (●, right side) to an input port (●, left side) of another node
   - **Secondary (click):** Click "↔ Connect" in toolbar, click source node, click target node
5. **Connection direction** — Edges flow left-to-right with arrowheads indicating direction; required for DAG validation and execution ordering
6. **Selecting nodes** — Click a node body to see its properties in the right panel
7. **Moving nodes** — Drag a node body to reposition on canvas
8. **Removing steps** — Select a step → click "✖ Remove Step" button in properties panel; bookend steps (Document Input, Generated Assets) are protected and cannot be removed
9. **Removing edges** — Click the `×` button next to any inbound/outbound edge in the properties panel
10. **Templates** — "Templates" section in left sidebar; click a template to create a new pipeline from it:
    - **Blank** — Only start/end bookend nodes (build from scratch)
    - **Default** — Full 6-agent pipeline with parallel Testing ∥ Documentation
    - **Code Only** — Minimal: Analyst → Developer
    - **Quick Prototype** — Analyst → Developer → Documentation
    - **Full QA** — All agents in strict sequence with strict quality gate (80, 3×)
11. **Toolbar actions** — Save, pipeline selector dropdown, Clone, Delete, Set Active, Validate, Layout, Connect mode, Undo (↩)/Redo (↪), Export JSON, Import JSON
12. **Validation** — DAG validation rules:
    - Must have at least one step
    - No duplicate step IDs
    - All steps must reference existing agent keys
    - All edges must reference existing steps
    - Must have at least one root step and one leaf step
    - No cycles (verified via Kahn's algorithm)
    - Document Input and Generated Assets bookend steps are required
    - Warning: missing input key coverage from upstream edges
13. **Properties inspector** — Agent info, Step ID, Model override, Temperature, Retry policy toggle/config, Inbound/Outbound edges with editable output key mapping, "Add Connection" button, "Remove Step" button
14. **Keyboard shortcuts** (planned): Delete key, Ctrl+Z, Ctrl+Y, Escape

## Task 2 — Workflow Designer Analysis & Improvements

### Industry Analysis

| Designer | Key Patterns | Relevance to Doc2Code |
|----------|-------------|----------------------|
| **Node-RED** | Port-to-port wiring, minimap, snap-to-grid, right-click context menus, flow tabs | High — same DAG paradigm, similar node density |
| **n8n** | Drag-to-connect, canvas zoom/pan, rubber-band multi-select, execution path highlighting | High — workflow automation with visual builder |
| **Azure Logic Apps** | Condition/branching nodes, run history overlay, expression editor inline | Medium — conditional branching maps to retry/quality gates |
| **Apache Airflow** | Topological execution order badges, Gantt chart execution view, task status colors | Medium — execution visualization during pipeline runs |
| **GitHub Actions (visual)** | YAML ↔ visual sync, job dependency arrows, matrix expansion preview | Medium — code artifact generation parallels |
| **Semantic Kernel Process** | Step-based pipeline with typed I/O, event-driven edges, state machine phases | High — closest architectural match to agent pipeline |

### Proposed Improvements (Ranked by Impact)

#### Priority 1 — Implement Now (High Impact, Low-Medium Effort)

| # | Improvement | Inspired By | Effort | Impact | Description |
|---|------------|-------------|--------|--------|-------------|
| 1 | **Port-to-port drag connections** | Node-RED, n8n | Medium | **High** | Task 1 above: visual connector ports on nodes, drag-to-connect with directed edges. Makes connections intuitive and directional. |
| 2 | **Edge labels on canvas** | Azure Logic Apps | Low | **High** | Show `OutputKeyMapping` value as a small text label at the midpoint of each SVG edge. Makes data flow visible without opening the properties panel. Implementation: add a `<text>` SVG element at the Bézier midpoint in `_redrawEdges`. |
| 3 | **Keyboard shortcuts** | All designers | Low | **Medium** | `Delete` key removes selected node/edge, `Ctrl+Z` undo, `Ctrl+Y` redo, `Escape` cancels connect mode. Add a `keydown` listener in `pipeline-canvas.js` that delegates to JSInvokable callbacks. |
| 4 | **Execution order badges** | Airflow | Low | **Medium** | After validation, display the topological execution order as small numbered badges on each node (e.g., ①②③). Shows users the runtime sequence. Implementation: add a badge overlay post-validation via a new JS function. |

| # | Improvement | Inspired By | Effort | Impact | Description |
|---|------------|-------------|--------|--------|-------------|

Phase 2 (Next sprint):    Items 5, 6, 7, 8      — zoom/pan, minimap, snap-to-grid, multi-select

### Architecture Considerations

- **State management:** All improvements should flow through the existing Blazor ↔ JS interop pattern (`JSInvokable` callbacks + `InvokeVoidAsync` calls). Canvas-level state (zoom, selection set, grid settings) lives in JS; pipeline data state lives in Blazor.
- **Performance:** For zoom/pan and minimap, use CSS transforms rather than re-rendering all nodes. Edge redraw on zoom must account for scale factor.
- **Persistence:** Zoom level, grid snap preference, and panel visibility should be stored in `localStorage` (per-user preference, not in pipeline definition).
- **Testing:** Canvas interactions are best verified via manual test plans or Playwright e2e tests (the `tests/e2e/` folder exists but is empty). Unit tests cover the underlying models and validator.
